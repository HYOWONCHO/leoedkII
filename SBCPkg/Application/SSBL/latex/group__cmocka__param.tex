\doxysubsubsection{Detailed Description}
Functionality to store expected values for mock function parameters.

In addition to storing the return values of mock functions, cmocka provides functionality to store expected values for mock function parameters using the expect\+\_\+\texorpdfstring{$\ast$}{*}() functions provided. A mock function parameter can then be validated using the check\+\_\+expected() macro.

Successive calls to expect\+\_\+\texorpdfstring{$\ast$}{*}() macros for a parameter queues values to check the specified parameter. check\+\_\+expected() checks a function parameter against the next value queued using expect\+\_\+\texorpdfstring{$\ast$}{*}(), if the parameter check fails a test failure is signalled. In addition if check\+\_\+expected() is called and no more parameter values are queued a test failure occurs.

The following test stub illustrates how to do this. First is the the function we call in the test driver\+:


\begin{DoxyCode}{0}
\DoxyCodeLine{\textcolor{keyword}{static}\ \textcolor{keywordtype}{void}\ test\_driver(\textcolor{keywordtype}{void}\ **state)}
\DoxyCodeLine{\{}
\DoxyCodeLine{\ \ \ \ expect\_string(chef\_cook,\ order,\ \textcolor{stringliteral}{"{}hotdog"{}});}
\DoxyCodeLine{\}}

\end{DoxyCode}


Now the chef\+\_\+cook function can check if the parameter we got passed is the parameter which is expected by the test driver. This can be done the following way\+:

\DoxyCodeLine{\{}
\DoxyCodeLine{\ \ \ \ check\_expected(order);}
\DoxyCodeLine{\}}

\end{DoxyCode}
